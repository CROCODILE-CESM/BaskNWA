# Oleander Study

This folder contains scripts to map CESM-MOM6 output into a predefined grid and at predefined dates and time, to later compute a climatology to compare with data from the Oleander Ship of Opportunity project.

**Goal**: Comparing model with observations

To achieve our goal we need output from an ocean model and observations. Our model of choice is CESM-MOM6, and our observations are temperature and velocities from the Oleander Ship of Opportunity project.

We also need to bring observations and model onto a shared space to compare apples with apples: we then use DART capabilities of interpolating model output onto the space of a set of observations. As we need to do this for multiple files, we will use `model2obs` orchestration capabilities instead of calling DART ourselves.

## Overall steps 

1. Identify target grid
2. Set up CESM-MOM6 run to store desired variables at desired depths
3. Run CESM-MOM6 case
4. Generate placeholder observations in space (i.e. target grid)
5. Replicate placeholder observations in time
6. Interpolate MOM6 output onto placeholder observations space
7. Build MOM6 climatology on target grid
8. Compare MOM6 climatology with climatology from Oleander measurements

### Steps 1-3

This folder focuses on mapping output to desired observations space, so here is just a recap of steps 1-3.

The Oleander travels weekly between New Jersey, USA, and Bermuda, UK, along a trajectory that can be approximated to a line. My **target grid** is then a transect, i.e. a vertical rectangle with sides New Jersey-Bermuda and 0-1000m depth. MOM6 outputs state variables onto the computational grid (horizontally), while the vertical resolution can be prescribed for diagnostic purposes. I then used MOM6 `diag_table` to store data at the vertical and temporal resolution that I desired (10m vertical, daily averages, 1 file per month). As MOM6 does not take custom horizontal locations to store diagnostics to outside of the grid, I interpolate the output in steps 4-6.

### Steps 4-6

To interpolate MOM6 onto the target grid (step 6) I need to use DART's [perfect_model_obs](https://docs.dart.ucar.edu/en/v11.20.1/assimilation_code/programs/perfect_model_obs/perfect_model_obs.html) program, which takes as input: i) MOM6 model data (the .nc files generated by CESM-MOM6 when I ran my case) and ii) observations locations and date-time in DART's [obs_sequence format](https://docs.dart.ucar.edu/en/latest/guide/detailed-structure-obs-seq.html). The latter is why I need steps 4 and 5, and the reason why they are two distinct steps is because DART also provides two programs that help with generating observation in space ([create_obs_sequence](https://docs.dart.ucar.edu/en/latest/assimilation_code/programs/create_obs_sequence/create_obs_sequence.html)) and then replicating them in time ([create_fixed_network_sequence](https://docs.dart.ucar.edu/en/v11.20.1/assimilation_code/programs/create_fixed_network_seq/create_fixed_network_seq.html)). The goal of steps 4 and 5 is to generate the target grid in obs_sequence format, so that step 6 can feed it to perfect_model_obs to map the model output to the grid.

Note that steps 4-6 here are a more-orchestrated and adapted version of creating synthetic observations as described [here](https://docs.dart.ucar.edu/en/v11.20.1/guide/creating-obs-seq-synthetic.html).

#### Step 4

create_obs_sequence uses as input values read from standard input (i.e. interactive command line). As I do not want to type each coordinate on my keyboard, copilot and I wrote `generate_create_obs_seq_input_file.py`. This takes a netCDF file with coordinates `lat`, `lon`, and `depth`, plus a list of DART [observation types](https://docs.dart.ucar.edu/en/latest/guide/difference-between-type-and-quantity.html), and generates a text file that can be passed to create_obs_sequence.

Example:

``` sh
python generate_create_obs_seq_file.py -i <file.nc> -t OBS_TYPE1 [OBS_TYPE2 ...]
```
